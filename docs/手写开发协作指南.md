# SupportDeskAgent 手写开发协作指南

## 目的

这个项目既是一个可展示的企业客服 Agent，也是一个系统学习 AI Agent 工程开发的实践项目。默认由项目作者亲自输入和实现代码，Codex 负责架构设计、任务拆解、注释化骨架、代码审查和排错指导。

这种方式比直接生成完整代码更慢，但能让项目作者真正理解：

- 每个文件为什么存在；
- 数据如何在前端、API、Agent 和数据库之间流动；
- LangGraph 的节点与状态如何协作；
- 为什么采用某种设计，而不是仅仅记住框架写法；
- 出现问题时应该从哪一层开始排查。

## 默认协作流程

每个新功能按照下面的顺序推进。

### 第一步：创建功能设计文档

Codex 在 `docs/features/` 中创建一个独立文档，先确定需求边界，不直接写业务代码。

文档需要回答：

1. 这个功能解决什么业务问题？
2. 用户如何触发它？
3. 数据从哪里来，最后保存到哪里？
4. 哪些模块参与，模块之间如何调用？
5. 哪些行为有外部副作用或安全风险？
6. 第一版明确不实现哪些内容？
7. 如何判断功能已经完成？

### 第二步：确定文件和职责

功能文档列出需要新增或修改的所有文件，并解释文件位置。

例如，一个新的 FastAPI 接口通常会拆分为：

- `api/schemas.py`：定义外部请求和响应结构；
- `api/routes.py`：处理 HTTP 协议和状态码；
- `services/`：编排业务用例；
- `agent/`：处理 LangGraph 状态和节点；
- `db/`：处理持久化；
- `tests/`：验证行为边界。

接口路由不应该直接编写复杂 Agent 逻辑，因为 HTTP 协议和 Agent 编排是两个变化原因不同的职责。拆开后，Agent 可以被测试、后台任务或其他接口复用。

### 第三步：给出严格的手写顺序

功能文档必须把实现顺序拆到足够小。每一步只引入一个可以理解和验证的变化，例如：

1. 先定义 Pydantic 输入模型；
2. 运行导入检查，确认字段和校验规则正确；
3. 再定义 LangGraph State；
4. 编写不依赖模型的纯函数节点；
5. 为节点补充单元测试；
6. 组装 Graph；
7. 最后接入 FastAPI 路由。

这样可以把错误限制在当前步骤，避免同时面对接口、模型和数据库三类问题。

### 第四步：提供注释化代码骨架

代码骨架默认全部处于注释状态，用于提示作者亲自手写。

Python 示例：

```python
# from pydantic import BaseModel, Field
#
#
# class ExampleRequest(BaseModel):
#     """定义接口输入边界，禁止路由直接接收结构不明的字典。"""
#
#     # TODO：添加 message 字段。
#     # 约束：不能为空，并限制最大长度，防止异常大请求进入模型调用。
#     # message: str = Field(...)
```

Vue 示例：

```ts
// import { defineStore } from "pinia";
//
// TODO：定义会话 Store。
// 这里仅保存跨组件共享的客户端状态，后端返回的数据交给 TanStack Query 管理。
// export const useExampleStore = defineStore("example", () => {
//   // TODO：声明状态和动作。
// });
```

骨架中的 TODO 应说明：

- 要实现的行为；
- 输入和输出；
- 必须满足的边界；
- 容易出现的错误；
- 完成后如何验证。

### 第五步：作者手写并分阶段验证

作者每完成一个小步骤，就运行文档中的最小验证方法。验证可以是：

- Python 模块导入成功；
- Pydantic 对非法数据返回预期错误；
- 单元测试通过；
- Graph 进入预期节点；
- API 返回约定状态码；
- Vue 页面出现正确的加载、成功或错误状态。

### 第六步：教学式代码审查

作者完成代码后，由 Codex 检查：

- 职责是否放在正确层级；
- 类型是否完整；
- 边界和异常是否覆盖；
- 注释是否解释了关键设计；
- 测试是否真正验证行为，而不是只执行代码；
- 是否存在为了暂时方便而留下的长期维护问题。

代码审查默认只指出问题和修改方向。只有作者明确要求直接修改时，Codex 才会编辑业务代码。

## 功能文档的完成标准

一个可以开始手写的功能文档至少应包括：

- 清晰的业务目标和非目标；
- 一张文字调用链或 Mermaid 流程图；
- 数据结构与状态变化；
- 文件清单及目录选择理由；
- 按依赖关系排列的实现步骤；
- 每一步的注释化代码骨架；
- 每一步的验证方法和预期结果；
- 常见错误与排查顺序；
- 安全、性能和可维护性考虑；
- 最终验收清单。
